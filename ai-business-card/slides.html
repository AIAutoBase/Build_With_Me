Build the AI Business Card · 30 min

Think. Prompt. Build. Git. Version. Deploy. Execute.

Say the word out loud at each step.

Step 1 · Think

The best prompt is a decision you made before you opened the AI.

  1. Who visits? A customer with a quick question.
  2. What do they need? Hours, prices, how to reach me.
  3. What is the smallest thing that solves it? Three pages and a bot that answers from facts I wrote.

Scope: Home, Chat, About. One config file. No database.

Step 2 · Prompt · paste into Claude Code, in an empty folder

The master prompt, and read what it writes

Build a 3-page static website: Home (index.html), Chat (chat.html), About (about.html). Rules: - Plain HTML/CSS/JS only. No framework, no build step. - Everything personal lives in config.json: name, tagline, logo path, accent color, about text + facts, contact links, and the chatbot (name, greeting, personality, knowledge list). Pages read config.json at load time. - Chatbot: chat.html posts to /api/chat. Write it as a Cloudflare Pages Function (functions/api/chat.js) that calls Google Gemini (gemini-2.5-flash) using env.GEMINI_API_KEY. The server builds the system prompt from config.json: answer only from the knowledge list, under 60 words, say it is an AI. Never expose the key to the browser. - Validate input in the function: last 10 messages, 500 chars each. - Mobile friendly, light/dark mode, accessible (labels, aria-live on the chat log). - Add a .gitignore that ignores .dev.vars, and a .dev.vars.example. Keep it as small as possible.

Reviewing the AI's code is the skill. Ask the room: what would you change before running this? The same text is in 03-MASTER-PROMPT.txt in the kit.

Steps 3 to 5

Make it yours, save it, name it

  • Edit only config.json: name, tagline, about, five to eight real facts.
  • Ask the bot something it knows, then something it does not. It should say it does not know.
git init -b main git add . git status # .dev.vars is NOT listed git commit -m "feat: first version of my business card" git tag v0.1.0

A commit is a save point. A tag is a name for a release. Secrets never go in git.

Steps 6 and 7

Deploy, then try to break it

npx wrangler login npx wrangler pages deploy . --project-name my-business-card npx wrangler pages secret put GEMINI_API_KEY --project-name my-business-card
  • The key lives in Cloudflare, not in your code and not in git.
  • Open your pages.dev address on your phone.
  • Pair up. Try to break your partner's bot.

Free Gemini quota is small. If you see 429, it is the free tier doing what it said.

Upgrade it with the NexGen kit · 13 min

Five parts, one page, one action

Heropromise, video, one button
Services3 or 4 cards
Workreal examples
Contacta form that delivers

Run one prompt. Look. Commit. Then the next.

Every word comes from config.json. Do not let the AI invent clients, numbers or testimonials.

NexGen kit · Step 1

Structure and content: five sections from config.json

Read config.json and the existing pages first. Add a landing page section structure to index.html, in this order: hero, services, work, contact, footer. - Hero: headline and tagline from config.json, one primary button that scrolls to the contact section, one secondary link to chat.html. - Services: 3 or 4 cards. Take the titles and one-line descriptions from a new "services" array in config.json. Add that array, with placeholder text I will replace. - Work: 2 or 3 cards from a new "work" array in config.json (title, one sentence, optional link). Mark placeholders clearly as placeholders. - Contact and footer: see the next prompt. Rules: plain HTML, CSS and JavaScript, no framework, no build step. Every piece of text comes from config.json. Keep it responsive, with the same light and dark mode as the existing pages. Clean typography, generous spacing, subtle hover states on cards and buttons. Do not invent claims, numbers, clients or testimonials.

Check: all five sections render, at phone width too. Commit: feat: landing page structure.

Every piece of text comes from config.json. The prompt tells the AI not to invent claims, clients, numbers or testimonials.

NexGen kit · Step 2, before the prompt

Get the video file ready first

  • Use the sample from class: hero.mp4 and hero-poster.jpg. Abstract, 8 seconds, under 300 KB, no logo.
  • Or your own: five to ten seconds, under 5 MB, slow motion, footage you have the right to use.
  • Put them at assets/hero.mp4 and assets/hero-poster.jpg.

Pages caps a single file at 25 MiB, and a phone on mobile data will not wait for more than a few.

Video tools queue and change their free limits. Step 2 is about placing and checking a video.

NexGen kit · Step 2

A hero video that does not look broken

Use assets/hero.mp4 as the background of the hero section, with assets/hero-poster.jpg as its poster image. - video attributes: autoplay, muted, loop, playsinline, preload="metadata". - Cover the hero with object-fit: cover. Do not stretch or distort the video, and do not scale it above its native resolution. - Put a dark gradient overlay between the video and the text, strong enough that the headline passes WCAG AA contrast (4.5:1) on top of the brightest frame. - If the user has prefers-reduced-motion set, do not play the video: show the poster image only. - If the video fails to load, the poster and the text must still look right.

Check: zoom to 200% and phone width for pixel breaks. Network tab: hero.mp4 under 5 MB. Turn on reduce motion: the video should stop. Commit: feat: hero video.

NexGen kit · Step 2, if it looks flat or muddy

Say what you see, not what you want

The hero text is hard to read over the bright part of the video. Increase the overlay contrast until the headline is clearly readable, without making the video look dead. Show me the CSS values you changed.

NexGen kit · Step 3

Contact form: one that actually delivers

Add a contact form to the contact section: name, email, message. - Labels on every field, visible validation messages, and aria-live on the status text. - Post to /api/contact, written as a Cloudflare Pages Function in functions/api/contact.js. - The function validates: name up to 100 characters, email shape, message up to 1000 characters. Reject anything else with a clear 400 message. - Add a hidden honeypot field that real people never fill in; drop those submissions quietly. - Send the email with the mail service I name, using a secret in env.CONTACT_API_KEY. Never put the key in the browser code or in git. Add the name of the variable to .dev.vars.example with no value. - On success show a thank-you message. On failure show the mailto link as a fallback.

Option A (today): a mailto button plus your booking link. Option B is this prompt. Test with a real message to yourself, then with the key missing: you should see the fallback, not a blank page.

NexGen kit · Step 4

Speed and polish

Audit index.html for load speed and fix what you find: - Images: set width and height, use loading="lazy" below the hero, convert large images to WebP. - Load nothing render-blocking that the hero does not need. - Add a scroll-triggered fade-in for the services and work cards using IntersectionObserver, disabled under prefers-reduced-motion. - Add hover states to cards and buttons that are visible but quiet. List every change you made and why.

Run Lighthouse (mobile) before and after. Write down Performance and Accessibility both times. Commit: perf: lazy images, scroll transitions.

NexGen kit · Step 5

Accessibility pass

Check the whole site for accessibility and fix it: - Every interactive element reachable and usable by keyboard, with a visible focus ring. - Skip link to main content. - One h1 per page, headings in order. - Alt text on every meaningful image, empty alt on decorative ones. - Form errors announced to screen readers. - Color contrast AA for all text, in light and dark mode. List what you changed.

Test it yourself: mouse aside, only Tab, Shift+Tab, Enter and Space across the whole page. Commit, tag v0.3.0, deploy.
