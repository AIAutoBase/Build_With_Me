Step 1 · Think

No keyboard. Three questions.

  1. Who visits? A customer with a quick question.
  2. What do they need? Prices, hours, how to reach me.
  3. What is the smallest thing that solves it?
Our answer: Home, Chat, About. One config file. No database.
Step 1 · Think

The best prompt is a decision you made first

Vague idea → vague app.
Clear scope → a prompt that fits on one screen.

Vague: "Make me a website with AI"
Clear: "3 pages, everything in config.json, chatbot answers only from my facts"
Step 2 · Prompt

The master prompt

Build a 3-page static website: Home, Chat, About.
- Plain HTML/CSS/JS. No framework, no build step.
- Everything personal lives in config.json.
- Chat posts to /api/chat: a Cloudflare Pages Function
  calling Gemini with env.GEMINI_API_KEY. Server builds the
  system prompt: answer only from the knowledge list,
  under 60 words, say it is an AI. Never expose the key.
- Validate input: last 10 messages, 500 chars each.
- Mobile friendly, light/dark, accessible.
- .gitignore for .dev.vars + a .dev.vars.example
Keep it as small as possible.

Full text in 03-MASTER-PROMPT.txt

Step 2 · Prompt

Read what the AI built

Reviewing AI code is the real skill. Ask:

  • Is anything personal hard-coded, or is it all in config.json?
  • Is the API key anywhere the browser can see it?
  • Did it add things I did not ask for?
  • Can I explain each file in one sentence?
Step 3 · Build

What you should have

my-business-card/
├─ config.json          ← YOU edit this
├─ index.html  about.html  chat.html

Step 3 · Make it yours

Edit one file: config.json

{
  "name": "Maria's Bakery",
  "tagline": "Fresh bread, every morning.",
  "logo": "assets/logo.png",
  "accent": "#c2410c",
  "about": { "text": "...", "facts": ["..."] },
  "bot": {
    "name": "Pan",
    "knowledge": [
      "Open Tue-Sun, 6am to 2pm.",
      "Sourdough loaf: $7. Custom cakes: 3 days notice."
    ]
  }
}

Use the worksheet (04-WORKSHEET.md). The bot only knows what you write.

Step 3 · Run it

Add your key, start the site

copy .dev.vars.example .dev.vars     # Mac/Linux: cp
# edit .dev.vars  →  GEMINI_API_KEY=your-key

npx wrangler pages dev .
# open http://localhost:8788
Test twice: ask something that IS in your facts, then something that is NOT. It should admit it does not know.
Why it works this way

The key never touches the browser

Wrong
Browser → Gemini
Key visible to anyone in dev tools
Right
Browser → /api/chat → Gemini
Key stays on the server. Rules are built there too.
Step 4 · Git

Save your work

git init -b main
git add .
git status        # .dev.vars must NOT be listed
git commit -m "feat: first version of my business card"
A commit is a save point you can always return to. Never put secrets in one.
Step 5 · Version

Name your releases

git tag v0.1.0
# change your accent color, then:
git commit -am "feat: new brand color"
git tag v0.2.0
git log --oneline
feat: → minor
fix: → patch
feat!: → major
Step 6 · Deploy

Put it on the internet

npx wrangler login
npx wrangler pages deploy . --project-name maria-business-card

npx wrangler pages secret put GEMINI_API_KEY \
    --project-name maria-business-card

npx wrangler pages deploy . --project-name maria-business-card
Use a unique project name. Deploy again after setting the secret.

Why we version

Break it. Roll it back.

git log --oneline
git checkout v0.1.0 -- config.json
git commit -am "fix: restore config from v0.1.0"

No file-old.json copies. Git already remembers every version.

Recommendations

Five rules to keep

  1. Keys live in .dev.vars and Cloudflare secrets. Nowhere else.
  2. Check git status before every commit.
  3. Tell visitors it is an AI. Never promise what you cannot deliver.
  4. Free quota is small. No rate limit yet. Fine for class, fix before promoting.
  5. Commit small, tag releases.
