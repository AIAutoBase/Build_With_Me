## Step 7 - The probe that decides whether half this class works

This is the important one.

The draft half of this class writes a reply into my Drafts folder using an IMAP APPEND.
"My provider supports IMAP" does NOT tell us whether APPEND works on my account, into
that folder, with the right flag. Three things have to be true at once.

The pack ships verify.sh, which probes it properly: it connects, finds my drafts folder,
appends a throwaway message with the \Draft flag, confirms it landed, and deletes it
again.

It needs three environment variables for that one run:

  export BRAIN_IMAP_HOST=imap.myprovider.com
  export BRAIN_IMAP_USER=me@myprovider.com
  export BRAIN_IMAP_PASS='...'

Rules for this:
  - I type the password myself. Do not ask me to paste it to you, and do not echo it
    back to the screen.
  - Do not write these into any file. They are for one run.
  - Tell me to unset them afterwards.

Then:
  bash class-05-hands-pack/verify.sh

Read the output to me. In particular, tell me:
  - THE EXACT NAME of my drafts folder - write it down where I can see it. There is no
    universal name; Drafts, INBOX.Drafts and [Gmail]/Drafts are all real.
  - whether APPEND was accepted
  - whether the probe message was found and then deleted

If APPEND is REJECTED: stop and tell me plainly that this half of the class cannot work
on my provider, and point me at docs/UPGRADE-gmail-api.md. Do not invent a workaround,
and do NOT suggest writing the draft into Postgres instead - a draft in a database is a
row, and nobody sends from a database.
