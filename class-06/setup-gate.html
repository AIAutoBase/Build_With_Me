Class 6 · See What Your Brain Knows

The parts only you can do

Five steps, about fifteen minutes, and no new signup. One of them is a check that lies to you, so read it rather than skimming.

Nothing here costs anything

No new account, no card, not even a free tier. The engine that names your graph is the Claude Code you installed in Class 1.

Do this on the machine your brain runs on

The one with Docker, n8n and Postgres — not necessarily the laptop in front of you. You need shell access to it.

1
Check your Python
terminal
python3 --version

You need 3.10 or newer. The teaching box has 3.13.5. If you are below 3.10, stop and upgrade before class — everything after this depends on it.

2
You cannot pip install anything

Try, and Debian says no:

what you get
error: externally-managed-environment

That is PEP 668, and it is correct behaviour, not a broken machine. Debian is protecting its own Python packages. The marker that turns it on:

see it for yourself
ls /usr/lib/python3.13/EXTERNALLY-MANAGED
Do not use --break-system-packages

The flag is named honestly. Use a virtual environment instead — that is step 3.

3
The check that passes while it is broken

The obvious way to test whether you can make a virtual environment:

DON'T use this as your check
python3 -c "import venv" && echo ok

It prints ok on a box where venv creation fails. We found this the hard way — the check went green and the venv failed a minute later.

The reason: venv the module is present, but ensurepip is not, and that is what installs pip into the new environment. Importing venv never touches it.

probe it for real
python3 -m venv /tmp/probe && echo "VENV WORKS" && rm -rf /tmp/probe

If that fails:

fix
sudo apt update && sudo apt install -y python3-venv

Then probe again. Do not continue until it prints VENV WORKS.

The lesson, which is bigger than this class

A check that cannot fail is not a check.

import venv could never have told you the truth, because it does not touch the thing that was missing. It made you feel checked without checking anything.

Same shape as Class 3's green execution storing the wrong data, and Class 4's audio file of the right size full of static. Ask what your check would print if the thing were broken. If the answer is "the same thing", it is not a check.

4
Make the real environment
on the brain machine
cd ~/brain
python3 -m venv .graphify-venv
source .graphify-venv/bin/activate
python -m pip install --upgrade pip

Your prompt should now start with (.graphify-venv).

Every new terminal needs this again
re-activate
source ~/brain/.graphify-venv/bin/activate

Forgetting it is the single most common way to get command not found: graphify on a machine where graphify is definitely installed.

Budget: 196 MB of disk once graphify is in, about 50 MB of RAM at rest.

5
Know which backend you are about to use

Read this even if you skip everything else. It is the one that quietly costs money.

Graphify picks a backend automatically by trying these in order:

graphify's detection order
gemini → kimi → claude → openai → deepseek → azure → bedrock → ollama

claude-cli — the free one we are going to use — is not in that list. It is never selected for you. You have to ask for it by name, every time:

always
graphify update . --backend=claude-cli

You have an OpenRouter key from Class 1. If it is exported as OPENAI_API_KEY, auto-detection reaches openai, finds it, and takes the paid path.

Free (claude-cli)Auto-detected paid
Outputidenticalidentical
Time to name 15 communities~10 s~10 s
Community namesgoodgood
Error or warningnonenone
Where the difference showsyour invoice, and nowhere else

Check what is exported on that box, before class:

terminal
env | grep -E "OPENAI_API_KEY|ANTHROPIC_API_KEY|GEMINI_API_KEY" || echo "none set - good"
You do not have to unset anything

Just know that you must pass --backend=claude-cli explicitly. If you want to prove the free path really needs no credentials, strip them for one run:

tested, not assumed
env -u OPENAI_API_KEY -u ANTHROPIC_API_KEY -u GEMINI_API_KEY \
  graphify update . --backend=claude-cli
6
Have something worth graphing

This class draws a picture of what your brain knows. A brain that knows nothing draws an empty picture, and you learn nothing from it.

  • Your Class 3 stack is running
  • There are real documents in it — the practice pack counts, your own paperwork is better
  • Your dashboard's Ask tab answers a question about them
Whole documents, not chunks

Graphify wants the document files. The rows in your Postgres kb table are ~180-word chunks cut for retrieval, which is a different shape. Know where your actual files live.

One expectation to correct

You cannot install Obsidian on your brain

If you have read about Graphify elsewhere it was probably paired with Obsidian. Obsidian is an Electron desktop app; your brain is a headless server. There is no desktop to install it into.

So the class default is the graph served from the dashboard you already have — a web page, reachable from any device on your network, nothing to sync.

Obsidian is still available on your laptop, and it is nicer to explore in. It just means getting the vault there. That is docs/UPGRADE-obsidian.md in the pack, and it is an upgrade rather than the main path on purpose.

command not found: graphifyThe venv is not activated in this terminal.
