## Step 7 - Prove the venv actually works, with a check that CAN fail

This is the part where the obvious check lies to you, so do it the way I am asking.

DO NOT use this as your check:

  python3 -c "import venv"

That prints ok on machines where creating a venv fails, because what is missing is
`ensurepip`, and importing venv never touches it. It is a check that cannot fail, which
means it is not a check.

Use a real probe instead:

  python3 -m venv /tmp/graphify-probe && echo "VENV WORKS" && rm -rf /tmp/graphify-probe

If it fails:
  sudo apt update && sudo apt install -y python3-venv
Then probe again. Do not continue until it prints VENV WORKS.

Also confirm python3 is 3.10 or newer. Stop if it is older.

Then explain back to me why the import check was insufficient. I want to hear you say
it, because this is the lesson the whole series keeps repeating in different clothes.

## Step 9 - Create the environment and install graphify

  cd ~/brain
  python3 -m venv .graphify-venv
  source .graphify-venv/bin/activate
  python -m pip install --upgrade pip
  pip install graphifyy

Note the spelling: the PyPI package is graphifyy with two y's; the command it installs
is graphify with one. That is not a typo.

Confirm:
  graphify --version

Tell me the version. This pack was measured against 0.9.49 - if mine is much newer, say
so, because something may have moved.

Then:
  graphify install --platform claude

Do NOT copy in any pre-packaged graphify skill folder you might find elsewhere. There is
a Windows-flavoured copy in circulation that is dozens of releases behind. The command
above fetches the correct current one.
