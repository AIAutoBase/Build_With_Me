Before the hour · 15 minutes

1
Python 3.10+, and a venv

Debian will not let you pip install system-wide, and it is right not to:

what you get if you try
error: externally-managed-environment

That is PEP 668, not a broken machine. Do not reach for --break-system-packages — the flag is named honestly. Use a virtual environment.

2
The check that passes while it is broken

The obvious way to test whether you can make a venv:

DON'T use this
python3 -c "import venv" && echo ok

It prints ok on a box where venv creation fails. We found that the hard way — the check went green and the venv failed a minute later.

The reason: venv the module is there, but ensurepip is not, and that is what puts pip inside the new environment. Importing venv never touches it.

probe it for real
python3 -m venv /tmp/probe && echo "VENV WORKS" && rm -rf /tmp/probe

If it fails: sudo apt install -y python3-venv, then probe again.

The lesson, and it is bigger than this class

A check that cannot fail is not a check.

Ask what your check would print if the thing were broken. If the answer is "the same thing", you do not have a check — you have a feeling.

3
The one that costs money, silently

Graphify picks a backend automatically by trying, in order:

graphify's detection order
gemini → kimi → claude → openai → deepseek → azure → bedrock → ollama

claude-cli — the free one we use — is not in that list. It is never selected for you. You ask for it by name, every time:

always
graphify update . --backend=claude-cli

You have an OpenRouter key from Class 1. If it is exported as OPENAI_API_KEY, auto-detection reaches openai, finds it, and takes the paid path.

Sit with that zero for a second

The shape of your knowledge is computed, not generated. No model is asked anything during the structural pass. The clusters, the connections, the hubs — all arithmetic.

The model is used for exactly one thing afterwards: giving the clusters names.

That is worth knowing about tools like this generally. Most of what looks like AI in a graph tool is arithmetic, and the AI part is a labelling convenience.

It clustered the class documents correctly with no help at all — the insurance policy, the warranty, the lease and the invoice each became their own community.

Graphify reports where every claim in the graph came from. That is Class 3's "I don't know" lesson, applied to a picture.

Why we read the report first, and not after

A picture is persuasive whether or not it is true, and once you have seen it you will believe it. Read the numbers while you can still be sceptical.

A graph that cannot tell you which edges are real is decoration.

The failure that looks like success

If your communities come back called Community 1, Community 2… the naming pass did not really run. It degrades gracefully instead of erroring, so you get a complete, beautiful, useless graph.

Good names use your vocabulary — your clients, your projects, your filenames. Generic names mean it never looked.

P3 — make it actually yours

P3
Vendor it, then serve it
0:30 – 0:44
graph.html is not self-contained

As graphify writes it, the page loads vis-network from unpkg.com. So the graph of your private business documents does not render unless a CDN is up — and it tells a third party every time you open it.

Fixing it is two steps: download one 687 KB file, rewrite one src. The pack ships vendor-vis.sh to do it.

This is the class about portability

Six weeks of your stack, on your machine would be an odd thing to end on a page that phones out to somebody else's server to draw itself.

prove it, don't assume it
grep -o 'src="[^"]*"' graph.html    # every result must be a local path
ls -l vis-network.min.js            # about 700 KB
head -c 100 vis-network.min.js      # must NOT start with <!DOCTYPE html>
A 1 KB library is a 404 saved to disk

In ls -l that failure looks exactly like success. Check the first bytes.

Then it goes on the dashboard you already have, as a Graph tab. Measured: HTTP 200 in 3 ms, from the LAN as well as localhost.

The gotcha that gets you next month

Re-running graphify update rewrites graph.html and the CDN link comes back. Re-run vendor-vis.sh after every rebuild — otherwise your offline page quietly becomes an online page, and you find out somewhere without internet, which is exactly when you wanted it.

Milestone

A Graph tab on your dashboard, loading from your own machine, working with the internet unplugged.

The limit worth repeating

A stale graph does not error. It answers.
