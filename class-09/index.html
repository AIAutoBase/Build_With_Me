Read this before class

Nothing in this class has been run against a live box yet. The pack is built, the guard is written, and its offline checker passes forty-five refusals and twenty allowed commands on a real machine. What has *not* happened is the cockpit being wired into a running dashboard and pointed at a real brain folder.

That is stated here rather than discovered by you at minute 20. The one thing you can prove before class, on your own machine, costing nothing, is that the guard refuses what it claims to refuse — and the installer runs exactly that check.

The one command

Fetch it to a file, then hand the file to Claude. Do not pipe it.

curl -fsSL -o install.txt https://aiautobase.github.io/Build_With_Me/class-09/install.txt && claude "Read install.txt in this folder and follow it exactly, from the top."

On Windows, use PowerShell rather than Command Prompt:

Invoke-WebRequest -Uri https://aiautobase.github.io/Build_With_Me/class-09/install.txt -OutFile install.txt; claude "Read install.txt in this folder and follow it exactly, from the top."

The installer downloads the pack, verifies its checksum, runs a safety scan on your existing setup, runs the guard checker, and stops. It starts nothing. That is deliberate.

What this class actually is

Class 8 gave you git. This one spends it.

The cockpit is a terminal inside the dashboard, running an agent with shell access to the folder that holds eight weeks of your work.

That sentence is the sales pitch and the warning, and it is the same sentence.

Three weeks ago, Class 8's decisions document promised this ordering in as many words: *you want git history before you hand an agent a shell.* The first two minutes of this hour are the payoff of that promise, not a new idea.

The installer will refuse you, and that is the point

If the folder is not a git repository, the installer stops. It does not offer to run git init for you.

That refusal is not caution, it is curriculum. Choosing what goes into a commit is the skill Class 8 spent an hour teaching, and an installer that chooses for you commits your .env on the way past — the exact failure that class exists to prevent.

If you skipped Class 8, take it first. The material is still up and it is sixty minutes.

The nine rules the guard enforces

RuleRefuses
1A shell metacharacter — a semicolon, pipe, ampersand, dollar, backtick, redirect, newline, $( or ${
2An empty command
3A command not on the allowlist
4A subcommand not allowed for that command
5A flag not allowed for that command
6A WRITE command while the cockpit is in READ mode
7A path resolving outside the pinned root
8.env, by name
9More arguments than the entry permits

Rule 1 is load-bearing. Once you refuse metacharacters outright you are no longer writing a shell parser — and every published escape of this shape is a bug in somebody's shell parser. Refusing a semicolon costs you pipelines and buys you the entire class of attack that composition enables.

Rule 7 compares resolved paths, not strings. String-matching on ../ is defeated by a symlink. Resolving first is defeated by nothing, because the answer it checks is the answer the operating system will actually use.

An allowlist, never a denylist

A denylist fails open by construction. It asks you to enumerate every dangerous string in a language designed for composition, and the attacker — or the merely confused agent — needs to find one case you missed. python -c on its own defeats every denylist that will ever be written.

An allowlist fails closed. Its worst case is a refused command and an annoyed member.

The five traps

TrapWhy it costs time
1Binding 0.0.0.0 to test from your laptopIt works immediately, exactly as hoped. No error, no symptom. You have published an unauthenticated shell, and the way you find out is that somebody else finds it first
2--dangerously-skip-permissionsEvery blocked prompt disappears and the agent gets faster and more capable. The cost stays invisible until the one command that mattered
3No output cap on the streamfind / sends tens of megabytes to a browser tab. The tab freezes, you force-quit, and the process keeps running with nothing reading it
4No timeout on spawnA command waiting on stdin waits forever. The tab shows a cursor. Nothing says the box now holds a zombie sitting on a database connection
5The agent helpfully fixes .envIt decides a variable looks wrong, rewrites the file, the encryption key changes, and every saved credential becomes undecryptable. It surfaces three days later as a login failure in n8n

What you can verify before class

node check-guard.mjs

Forty-five refusals, each with the rule number expected to catch it. Twenty commands that must be allowed — the shorter half, and the one that proves the guard is not a brick.

It spawns nothing to produce that table. It is the only file in the pack that is safe to run before class, and it is the only one the installer runs.

Once you have written your own guard in class, point the checker at it:

node check-guard.mjs --guard ../brain/cockpit/guard.mjs

What this does not protect against

Stated here rather than left for you to find out.

  1. An agent in WRITE mode with a scripting language on the allowlist can read any file on

the box, and rule 8 becomes decoration. The default allowlist has no python and no node -e, on purpose. Adding one is a decision, not a convenience.

  1. A command that is allowed and wrong. mv is on the WRITE list. The guard has no

opinion about whether you wanted that file moved. Git is the answer, which is why Class 8 came first.

  1. Anything reached before the guard. It protects the command path. It does not protect

the dashboard's other routes, the database, or the box.
