2
n8n, self-hosted
VPS from ~$68/yr
This will not work on n8n Cloud

The workflow shells out to ffmpeg six times and uses Execute Command. n8n Cloud allows neither. This is not a preference.

A small VPS running Docker. 2 GB of RAM is enough — the class box is a Mac Mini with 3.7 GB and it renders fine, just not fast.

Five lines decide whether video works at all. Get these into your docker-compose.yml before you import anything:

docker-compose.yml
    image: rxchi1d/n8n-ffmpeg:latest      # the official n8n image has NO ffmpeg
    environment:
      NODES_EXCLUDE: "[]"                 # re-enables Execute Command
      N8N_RESTRICT_FILE_ACCESS_TO: ""     # lets nodes read and write /videos
      N8N_DEFAULT_BINARY_DATA_MODE: filesystem
    volumes:
      - ./videos:/videos
The one nobody thinks to set

N8N_DEFAULT_BINARY_DATA_MODE: filesystem. Without it n8n holds every video in RAM. A 1080×1920 vertical goes through six ffmpeg nodes, and on a small box n8n gets killed partway through and reports nothing useful — it just stops.

Then on the host, next to your compose file:

terminal
mkdir videos
sudo chown -R 1000:1000 ./videos
sudo chmod -R 775 ./videos
docker compose up -d

1000 is the uid n8n runs as inside the container. If your login user is already uid 1000 (id will tell you), the chown changes nothing and that is fine.

8
Google Drive
free · 20–30 min

Stores avatars, music and finished video. Two separate jobs here, and the second is the one people are not expecting.

a) The folder. Make one, copy the folder ID from the end of its URL.

Set sharing to "Anyone with the link" → "Viewer"

Skip this and Replicate and Blotato cannot fetch your files. Both fail with an error that does not say why.

b) Google authentication — budget 20 to 30 minutes.

A folder ID is not access. n8n needs an OAuth credential to write into your Drive, and that means a Google Cloud project, a consent screen and a client ID. It is the longest single item in this whole setup, and it is one-off and free.

Google Cloud Console →
Follow GOOGLE-AUTH.md in the pack — do not improvise it

There are four places this fails with an error that names the wrong cause. The most common is redirect_uri_mismatch, which means the URL you pasted into Google does not exactly match the one n8n shows — copy it from n8n rather than retyping it, protocol and port included.

The one that breaks a week later

Leave the OAuth app in "Testing" with External user type and Google expires your consent and refresh tokens after seven days. Content Mate runs on a schedule, so your uploads just stop, quietly.

Publish the app to "In production." Free, does not make anything public, and it is the difference between a setup that lasts and one that dies next Tuesday.

Name the credential exactly Google Drive account

The workflow ships with credential ids stripped so n8n matches by name. The right token under the wrong name attaches to nothing.

The one ordering rule that ruins the import

Install the Blotato node BEFORE importing the workflow — and from the n8n interface

Import first and the nine Blotato nodes arrive as unrecognized types.

Install it from a shell instead of the interface and you get this, which names a file that is right there on disk:

Failed to load package "@blotato/n8n-nodes-blotato"
Error: Cannot find module './toString'

Blotato declares n8n-workflow as a peer dependency and npm 7+ installs peers by default, dropping a second copy into .n8n/nodes/node_modules. The path it resolves from is what is wrong, not the file.

Right-click the canvas → add node → search Blotato → Install. Already broke it from a shell? Delete .n8n/nodes/node_modules and start over.
