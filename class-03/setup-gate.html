01

Create your n8n account

It runs on your machine. This account is local — nobody else can sign in to it, and there is nothing to verify by email.

Pick any email and a password you will remember. Write the password down. There is no reset link, because there is no server to send you one.

Open n8n http://localhost:5678
First boot takes 60–90 seconds. n8n is running its database migrations. If the page will not load yet, wait and refresh — it is not broken. A 404 at the root address is also normal on n8n 2.x; the editor lives at /home/workflows.

02

Get an OpenRouter key, and put money on it

This is the one part of the build that is not yours. It turns your documents into numbers, and it charges you to do it.

Sign up, then create a key, then add credit. All three, in that order. A key with no balance is the single most confusing failure in this class, so do not stop after step two.

1. Sign up 2. Create a key 3. Add credit openrouter.ai · keys · settings/credits

How much. Add the smallest top-up the page offers. Embedding this whole practice pack costs a fraction of a cent — you are not buying credit you will use, you are buying a balance that exists. Whatever you put on it will still be sitting there after Class 4.

Copy the key the moment it appears. OpenRouter shows it once and never again. If you lose it, delete that key and make another one; there is no way to read it back.

A key with no balance does not say "you are out of money". It fails with an authentication error that reads like the key is wrong, and you will spend an hour re-typing a key that was always correct. If anything breaks after this, check your credits first.

03

Put the key into n8n as a credential

A credential is stored encrypted and travels by name. A key typed into a node travels inside every export you ever share.

In n8n: Credentials → New → Header Auth. Three fields.

Open n8n credentials http://localhost:5678/home/credentials
FieldWhat to type
NameOpenRouter — spelled exactly like that, it is what the workflows look for
Header NameAuthorization
Header ValueBearer then your key. The word Bearer, then one space, then the key.
Never paste a key into a node parameter. That is why the files in this pack are safe to hand around: they carry the credential's name, never its value. Do it the other way once and your key is in every copy of that workflow, forever.

04

Point the Postgres credential at brain

This is the most common mistake in the whole class. It costs people an hour and the error never mentions the database name.

Your Postgres credential from Class 2 probably says database n8n. It needs to say brain. Open it, change that one field, save.

Open n8n credentials http://localhost:5678/home/credentials

Get this wrong and everything connects, everything looks healthy, and every query comes back empty — because it is looking in a database where your documents were never stored. You will see relation "kb" does not exist and go hunting for a table that is sitting perfectly intact one database over.

05

Import the workflows, then activate them

Saving is not activating. An inactive workflow answers 404, and that is the most common "it's broken" moment of the class.

From the pack folder, import both files from demo/:

  • 05-kb-ingest.json — document in, chunks and numbers out
  • 06-kb-ask.json — question in, grounded answer or a refusal out

In n8n: Workflows → Import from File. Then open each one and turn on the Active toggle in the top right. Both of them.

Open n8n workflows http://localhost:5678/home/workflows

Then open each Postgres and HTTP node and re-select your credential from the dropdown. n8n gives credentials their own IDs on every machine, and the IDs written in these files are from the machine they were built on. A node with a credential it cannot find shows a small warning and then fails at run time with an authentication error that has nothing to do with your key.

You can build these yourself from prompts/P2-ingest.md and prompts/P3-ask.md instead. Same result, and you learn more — the demo/ files are the fallback, not the lesson.

If something here will not work

What you seeWhat it means
The n8n page will not load at all Give it 90 seconds from first start, then refresh. Still nothing: docker compose ps — both containers must say Up.
404 at http://localhost:5678 Normal on n8n 2.x. The editor is at /home/workflows.
{"code":503,"message":"Database is not ready!"} n8n lost the startup race to Postgres. docker compose down && docker compose up -d — restart will not fix it.
An auth error after you added the key Check your OpenRouter credits before you check the key. It almost always means the balance, not the key.
404 from the ask webhook The workflow is saved but not Active. Step 5.
Everything green, every answer empty The Postgres credential is on the n8n database. Step 4.

Still stuck? Post it in the community — the exact command and the exact error, pasted, not described. Half of these get answered in a minute by someone who hit the same thing last week.
